Providers: SabrTrader.Pipeline.Providers
An IDataProvider is the market-data port of one connected venue: it advertises a ProviderCapabilities flag set and exposes the feeds it supports as nullable properties. A plugin does not construct one directly; the host builds it through the venue seam (IVenuePlugin → IVenueDescriptor → IVenueSession.Data); see the Venue seam reference and the Venue plugins chapter. Optional facets OF the data plane are probed with AsCapability<T>() rather than added as properties here.

One capability covers the whole continuous-contract story: a server-stitched symbol, the dated contract that series is on right now (the venue then decides the product's roll; a venue that cannot say it offers no series, and the platform stitches its dated contracts on its own roll dates), and the cached per-contract tick source for continuous tick replay. IProviderClock	DateTime? NowUtc { get; }: the provider's own notion of "now", in the convention its bars and ticks are stamped. It keeps a chart agnostic to live versus replay: the chart asks the provider what time it is instead of assuming wall-clock. Null means no session clock (a replay provider with nothing loaded); wall-clock is never reported as provider time. Read live: a replay clock advances as playback runs, so callers re-read rather than cache. Providers that do not implement it are treated as real-time.

Backfill & ticks: SabrTrader.Pipeline.Runtime
IBackfillProvider and its refinements are the consumer-facing history surface. A venue plugin normally gets them from the backfill composer, which builds the cached chain from the history sources in the storage seam; implement a refinement directly only when your venue serves it natively. The host probes for each refinement. ITickSource delivers live ticks.

ILiveHistoryProvider	bool ProvidesLiveHistory { get; }, Task<LiveHistory> LoadLive(BarSpecification spec, LiveHistoryRequest request, ct). Optional capability of a backfill provider: load a series' history for a consumer that goes live afterwards, as one answer that carries the still-forming bar and exactly how far its data reaches. Probe ProvidesLiveHistory before calling; LoadLive throws InvalidOperationException when it is false. The chain the backfill composer builds implements it. A decorator serves live history only when the provider it wraps does, transforms the bars exactly as its Load does, and keeps the reach only while the forming bar stays the last bar.
LiveHistoryRequest	record (DateTime AsOfUtc) with init DateTime? FromUtc, DateTime? ToUtcExclusive, TimeSpan? Lookback, IProgress<BackfillProgress>? Progress, OrderFlowResolution? OrderFlow (null for bars only), string? TickSizeInstrumentId. AsOfUtc is the one instant the history reaches and live ticks take over from; every "is this bar still forming" decision is made against it. The window is [FromUtc, ToUtcExclusive): the end defaults to AsOfUtc and is never after it, the start defaults to the end minus Lookback, and Lookback to the provider's default depth. A window that ends before AsOfUtc must name its start or its lookback. Methods: (DateTime FromUtc, DateTime ToUtcExclusive) ResolveWindow(TimeSpan defaultLookback) gives the concrete window given your default depth; bool TryGetExplicitWindow(out DateTime fromUtc, out DateTime toUtcExclusive) is true when the request names absolute instants (a start, or an end plus a lookback) and false when it reaches AsOfUtc from a depth; OrderFlowBackfillRequest ToOrderFlowRequest() builds the equivalent order-flow load (explicit window when there is one, else the lookback) and throws when OrderFlow is null; Validate() throws when the instants are not UTC or the window cannot be described.
LiveHistory	LiveHistory(IReadOnlyList<Bar> bars, IReadOnlyList<OrderFlowBar>? orderFlow, LiveHandoffPoint? formingReach): Bars (oldest first), OrderFlow (index-aligned with Bars, or null when the load carried none), FormingReach. The reach is set only on a still-forming last bar and says how far its data goes: live ticks at or before it are already in the bar, every later tick extends it. Null means the provider cannot say, and the bar is taken as a snapshot through AsOfUtc. The constructor throws when the footprint list is not index-aligned or the reach lies outside the last bar.

Only valid on an Auto request and never Auto itself. string? TickSizeInstrumentId: the instrument whose tick size prices this load when it is not the requested one; the continuous-futures stitch names the front month here for each older month's slice, because an expired month has no reference data left to read its own tick size from. OpenInterestBackfillRequest	record (DateTime? FromUtc = null, DateTime? ToUtcExclusive = null, TimeSpan? Lookback = null, IProgress<BackfillProgress>? Progress = null): HasRange, HasLookback, Validate().
ITickSource : IDisposable	IDisposable Subscribe(string instrumentId, Action<Tick> onTick); plus a default-implemented routed overload Subscribe(string instrumentId, string? exchange, Action<Tick> onTick) that delegates to the plain one. Exchange travels on the REQUEST: a venue that serves the same instrument from several exchanges overrides the routed overload, a single-feed venue inherits the default. A DECORATOR must override and forward it, or the picked exchange is dropped and the chart mixes feeds.
ITimeBarPeriodSupport	bool SupportsNatively(TimeSpan period), TimeSpan? LargestNativeDivisor(TimeSpan period); extension TimeBarPeriodSupportExtensions.CanServe(period) refuses timeframes the venue cannot serve. Two implementations ship: LadderTimeBarPeriodSupport, for a venue with a fixed ladder of native periods (see the venue seam), and AnyWholeSecondPeriodSupport, for a venue that publishes no period ladder. AnyWholeSecondPeriodSupport.Instance is its one shared instance (the class is sealed and has no public constructor): SupportsNatively is true for every positive whole-second period, and LargestNativeDivisor always returns null, because a whole second divides only whole-second periods and those are already native. The host uses it when a venue states no period support of its own, so a venue only passes it to say so explicitly.

Storage seam: SabrTrader.Pipeline.Storage
Two halves. The history sources (IHistoricalTimeBarSource, IHistoricalTickSource, IHistoricalOrderFlowBarSource, INativeBarSource) are what a venue implements and hands to the backfill composer. The other half is the host's local tick/bar cache: the host reads what it already holds and asks your sources only for the DateRanges still missing.

LiveHandoffPoint	record struct (DateTime At, int HistoricalTradesAtInstant): where a series' history ends and live ticks take over. Every tick stamped before At is history, and so are the first HistoricalTradesAtInstant trades stamped exactly At; every other tick is live. The count matters because several trades often share one exchange timestamp, and history and the live feed deliver them in the same order. Factories: Before(at) (everything before, nothing at it, as at a closed time bar's end), Through(at) (everything at or before, as for a snapshot taken at that instant), AfterLastOf(IReadOnlyList<Tick> ticks) (exactly those ticks; throws on an empty list). The count is never negative.
DateRange	record (DateTime FromUtc, DateTime ToUtcExclusive): IsEmpty, Length, Contains(utc), Overlaps(other), TouchesOrOverlaps(other).
CacheProviderKey	CacheProviderKey.Normalize(providerKey): the provider namespace the host's caches key under. DepthStoreKey normalises its provider key through it.
BackfillSourceUnavailableException	Exception a history source throws when the venue could not be asked: not connected, unreachable, 5xx or 429, timed out. The cache serves what it has, leaves the window missing and stops asking the venue for the rest of that load.

Host-side types
These types sit in the same namespaces as the provider surface. The host and first-party venues use them; a plugin reads them at most.

Type	What it is
IInstrumentAdjustmentResolver	Task EnsureAdjustmentVersionAsync(string instrumentId, ct): an optional companion to IInstrumentMetadata for a venue whose corporate-action version needs an async lookup. The cache awaits it before building a time-bar cache key, so a new split invalidates cached bars on the first request.
AsyncSerialRequestQueue · RequestPriority	SabrTrader.Pipeline.Async: a single-slot async queue. ExecuteAsync(work, ct) and ExecuteAsync(work, RequestPriority priority, ct) (plain and Task<T> forms) run at most one body at a time across callers; RequestPriority.High cuts in front of every queued Normal request. A venue uses it to serialise requests to an API that allows one in flight.
IPerfRecorder · PerfEvent · PerfStats · PerfStatsKey · PerfStatsSnapshot	SabrTrader.Pipeline.Perf: the host's timing recorder behind the Task Manager. BeginScope(category, detail?, chartId?) returns a PerfScope (a disabled recorder returns PerfScope.Disabled, the no-op scope whose Dispose does nothing, so an instrumented hot path costs one branch while recording is off); Snapshot(lookback) returns per-key PerfStats (Count, TotalMs, MinMs, MaxMs, MeanMs, P50Ms, P95Ms) and the raw PerfEvents (Category, Detail, ChartId, StartTimestamp, ElapsedTicks, ManagedThreadId).
